# OpsBench E2E Cases

This repository contains reproducible E2E task packages generated by
`opsbench-factory`.

## Releases

- `releases/e2e-pilot-v0.2/`: the current 11-case pilot extracted from the
  available runtime-capable case pool.
- The formal 48-case benchmark is not released yet. The pilot is explicitly
  marked `pilot_incomplete` and is not a claim of balanced coverage or
  calibrated difficulty.

The repository keeps the earlier three-case demo at the root for history.

## Current pilot status

The pilot contains 11 statically valid case packages:

| Primitive | Count | Target difficulty |
|---|---:|---|
| `http_wrong_port_v1` | 4 | medium |
| `linux_cpu_runaway_v1` | 4 | medium |
| `linux_cpu_runaway_v2` | 1 | medium |
| `nginx_bind_conflict_v1` | 1 | easy |
| `postgres_missing_index_v2` | 1 | hard |

Three corresponding demo cases have completed the full Docker runtime gate.
The remaining eight pilot cases are statically valid but are retained as
runtime-pending until their individual control reports are completed.

## Running a local case

Use the `opsbench-factory` CLI from the source project:

```powershell
opsbench validate-e2e --case-root releases/e2e-pilot-v0.2/cases/private
opsbench eval e2e-manifest `
  --case-root releases/e2e-pilot-v0.2/cases/private `
  --sample-size 11 `
  --sample-seed 42 `
  --output releases/e2e-pilot-v0.2/results/e2e_manifest.json
```

The complete local package is under `cases/private`. It contains the hidden
scenario and verifier needed for local reproducibility. The corresponding
`cases/public` projection contains only the task, tools, and public manifest.
Do not treat the `private` projection as a blind external test set when this
repository is cloned by an evaluator.

To run the ReAct agent, configure the API key in the local environment only;
no key is stored in this repository:

```powershell
$env:OPSBENCH_API_KEY = "<your-key>"
$env:OPSBENCH_BASE_URL = "<provider-base-url>"
$env:OPSBENCH_MODEL = "deepseek-v4-flash"
```

## Provenance and results

Each release contains:

- `dataset_manifest.json`: frozen case inventory and release status;
- `provenance/cases.jsonl`: source and digest provenance;
- `results/e2e_manifest.json`: local evaluation manifest;
- `results/runtime_status.json`: distinction between static validation and
  completed runtime gate;
- `docs/`: package layout and paper-facing notes.

The benchmark is document-driven, but the current pilot is a case-pool
snapshot. Missing capability quotas must be filled by generating new
document-grounded cases and passing the full runtime gate before a formal
release is claimed.
